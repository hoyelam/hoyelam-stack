# Workflow reflection automation

## Intent

Review completed engineering work for repeated friction, user corrections, and reusable verification discoveries that may improve `hoyelam-stack`.

## Required configuration

1. Path to the `hoyelam-stack` repository.
2. In-scope completed tasks or repository history.
3. Time window for evidence.
4. Output location for the proposal.

## Execution

1. Read `skills/reflect-workflow/SKILL.md` and the current stack before evaluating gaps.
2. Reconstruct only the configured tasks and their final repository states.
3. Require the evidence gate for every proposed rule.
4. Check whether an existing skill, agent, automation, test, or script already covers the lesson.
5. Prefer structural enforcement over more prose.
6. Produce a ranked proposal with evidence, overlap, expected benefit, and validation plan.
7. Do not edit the reusable stack unless the automation was explicitly configured and authorized to apply approved proposals.

## Boundary

1. Do not read unrelated tasks or repositories.
2. Do not copy private source or conversation text into the proposal.
3. Do not create issues, pull requests, messages, or releases unless separately authorized.
4. Do not turn one-off preferences into universal workflow rules.
