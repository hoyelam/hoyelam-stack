# Full quality pass automation

Apply the personal defaults in the installed `$hoyelam-mode` to an already-implemented branch. This pack stays dormant until configured.

## Configuration

Identify the repository, branch, base, writable scope, intended outcome, and required checks. Include supported verification commands and runtime prerequisites when the changed behavior needs them. State whether pushing or external reporting is authorized.

## Work

Confirm the configured scope against the live repository. Use existing checks and relevant runtime paths to assess the intended outcome. Select deeper verification or review skills when useful; delegate independent work where it improves speed or confidence.

Validate findings before fixing them within configured authority. Rerun affected checks after fixes and inspect the revised result. Report actual evidence, current state, and remaining gaps. Required verification that fails or is blocked remains incomplete.

Do not merge, deploy, release, broaden scope, or create a competing pull request. A worker report or readiness check alone does not establish behavior.
