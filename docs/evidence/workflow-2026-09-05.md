# Workflow implementation exercise — 2026-09-05

Three isolated Python CLI tasks produced working local changes. Independent replay confirmed their regression coverage and output behavior. The task with an unavailable required smoke check correctly remained incompletely verified.

This is evidence for those tasks, not a reliability estimate for all projects or a comparison with the previous workflow.

## Method

Before execution, the controller recorded criteria for planning, direct behavior proof, review resolution, scope preservation, and completion claims. Separate workers received ordinary implementation requests, project instructions, and a frozen copy of the revised workflow. They received no conversation fork, controller criteria, expected implementation, or other workers' results.

The controller then inspected actual source changes, ran the workers' final tests against both starting and final source in fresh copies, and independently invoked the final CLIs. Source inputs, outputs, workflow hashes, check scripts, and command results are preserved in the [evidence bundle](workflow-2026-09-05.json).

No skips were reported in the final task suites. Only task source, tests, and Reportkit usage documentation changed. The catalog finding was deliberately supplied as review feedback; the exercise does not claim an independent reviewer discovered it. The unavailable deployment check was deliberately supplied by the fixture and did not contact a live system.

The Reportkit worker reported an automatic approval rejection for its test edit, then reported that the same patch retry succeeded after the parent clarified the user's authorization. Its message and final answer are retained in the bundle. This chronology is worker-reported; underlying approval and patch events were not independently captured. The controller independently confirmed that the final deployment check remained blocked.

## What this does and does not prove

- Independent replay confirms the two regression fixes, supported review resolution, and final local feature behavior. It does not establish the ordering of the workers' original commands.
- Full worker activity timelines were not independently captured. Planning before editing is **unobserved**, even where a worker reported following the sequence. No claim of compliance relies solely on that report.
- The blocked check remained required and unchanged, and the worker's final answer explicitly withheld a completion claim. This directly supports the completion-reporting rule in this task.
- These were small constructed Python projects using one workflow variant. Multi-unit dependency sequencing, production applications, platform verification, and reliability across agents were not exercised.
- A separate read-only reviewer inspected the stack's complete scoped diff and reported no supported findings. Its focused validator run passed 8 tests. The parent ran the complete repository suite and the three changed skill validators. This is separate evidence from the task exercise.

The exercise supports keeping the revised workflow. It does not justify adding more universal rules or claiming improvement over an earlier variant. A future broader exercise should capture task-local activity and include dependent implementation units if those properties need stronger proof.
